# Gestion-Academica -> AcademicCore migration (F4.1) — runbook and evidence

## Runbook (user data)

The personal Gestion database and `documentos/` folder are not in any
repository; the user runs the migration on their machine:

```python
from academic_core.application import AcademicApp
from academic_core.application.gestion_migration import MigrationOptions
from academic_core.config import Settings

app = AcademicApp(Settings.load())
opts = MigrationOptions(documents_dir=r"<gestion>\documentos",
                        degree_total_credits="240",
                        final_project_names=("Trabajo de Fin de Grado",))
dry = app.migration.dry_run(r"<gestion>\academico.db", opts)          # 1. zero writes
print(dry.lossless, dry.errors, dry.counts, dry.evaluation_check)     # 2. review
rep = app.migration.apply(r"<gestion>\academico.db", opts,
                          snapshot_dir=r"<backups>")                   # 3. snapshot + apply
assert rep.lossless and not rep.validation_failures                   # 4. post-validation
```

- The legacy DB is opened read-only (`mode=ro` + `query_only`); files are
  only read under `documents_dir` (traversal/symlink/size refused).
- Re-running is safe (idempotent). Rows preserved because a file was
  missing are migrated by a later run once the file is available.
- `progress(stage, done, total)` and `cancel()` callbacks are supported;
  cancelling leaves the target database unchanged.
- Recovery: the snapshot in `snapshot_dir` (SHA-256 in the report) is a
  consistent SQLite copy taken before any write.

## Mapping summary

See `GESTION-F4.1-DELTA-MAP.md`. Every source row ends in `legacy_map`
(migrated) or `legacy_payloads` (verbatim JSON + reason + deferred phase).

| Kept verbatim (phase) | Tables |
|---|---|
| F14 PDF annotations | `marcador`, `anotacion_pdf` |
| F12 notifications | `aviso_descartado` |
| F4.2 search favourites/recents | `busqueda_favorito`, `busqueda_reciente` |
| legacy classifier (superseded) | `apartado` (name also copied into each document's `legacy`) |
| data refused by an invariant | any row; `errors` lists it; nothing is dropped |

### C. Synthetic 29-table fixture on the real schema (tests)

`tests/test_f4_migration_dryrun.py` covers every table and edge case:
missing file, traversal path, opaque zip, byte-identical duplicates (same
and different subject), homonym professors, duplicate professor link,
subject-less task, start-without-end, study space documents/goals,
fortnightly series, settings, deferred tables, idempotency, cancellation,
determinism across `PYTHONHASHSEED` 0/11/2024/random, read-only source.
